# Sitemaps management API

The **Sitemaps** feature (`OrchardCore.Sitemaps`) manages the tenant's sitemaps, sitemap indexes and their sources. It advertises the `sitemaps` remote-management capability and contributes the `pomi sitemaps` commands and MCP tools.

For the module's concepts, see the [Sitemaps module](../../modules/Sitemaps/README.md). When SEO is also enabled, the `sitemaps-robots` [settings section](../settings/README.md) controls `includeSitemaps`, with `ManageSeoSettings`.

## Authentication and permissions

Every operation requires an `Api` scheme bearer token, **Access remote management API** (`AccessRemoteManagement`) and **Manage sitemaps** (`ManageSitemaps`). An absent or invalid token returns `401`, a missing permission returns `403`.

## Base route

`/api/sitemaps`, and `/api/sitemap-source-types` for the source types.

## Endpoints

| Method | Endpoint | Operation ID | Pomi command |
| --- | --- | --- | --- |
| `GET` | `/api/sitemaps` | `ApiListSitemaps` | `sitemaps list` |
| `GET` | `/api/sitemaps/{id}` | `ApiGetSitemap` | `sitemaps show <id>` |
| `POST` | `/api/sitemaps` | `ApiCreateSitemap` | `sitemaps create` |
| `PUT` | `/api/sitemaps/{id}` | `ApiUpdateSitemap` | `sitemaps update <id>` |
| `DELETE` | `/api/sitemaps/{id}` | `ApiDeleteSitemap` | `sitemaps delete <id> --force` |
| `POST` | `/api/sitemaps/{id}:enable` | `ApiEnableSitemap` | `sitemaps enable <id>` |
| `POST` | `/api/sitemaps/{id}:disable` | `ApiDisableSitemap` | `sitemaps disable <id>` |
| `GET` | `/api/sitemap-source-types` | `ApiListSitemapSourceTypes` | `sitemaps sources types` |
| `GET` | `/api/sitemap-source-types/{type}` | `ApiGetSitemapSourceSchema` | `sitemaps sources schema <type>` |
| `GET` | `/api/sitemaps/{id}/sources` | `ApiListSitemapSources` | `sitemaps sources list <id>` |
| `POST` | `/api/sitemaps/{id}/sources` | `ApiCreateSitemapSource` | `sitemaps sources create <id>` |
| `PUT` | `/api/sitemaps/{id}/sources/{sourceId}` | `ApiUpdateSitemapSource` | `sitemaps sources update <id> <sourceId>` |
| `DELETE` | `/api/sitemaps/{id}/sources/{sourceId}` | `ApiDeleteSitemapSource` | `sitemaps sources delete <id> <sourceId> --force` |

These operations are MCP tools, except the deletions, which need `AllowConfirmationRequiredTools`. See [MCP server](../../modules/RemoteManagement/README.md#mcp-server).

## Sitemaps

### Sitemap representation

```json
{
  "id": "3m8f1w6zq",
  "name": "Main",
  "path": "main.xml",
  "kind": "Sitemap",
  "enabled": true,
  "sourceCount": 1,
  "containedSitemapIds": []
}
```

`kind` is `Sitemap` or `SitemapIndex`. `containedSitemapIds` holds the regular sitemaps of an index. Cache paths and arbitrary source properties are not returned.

### List sitemaps

`GET /api/sitemaps`

| Location | Name | Type | Required | Description |
| --- | --- | --- | --- | --- |
| Query | `skip` | integer | No | Zero-based offset. Default `0`, minimum `0`. |
| Query | `take` | integer | No | Page size. Default `50`, range `1`–`200`. |

`200` returns an array ordered by name, without a count. Other paging values return `400`.

### Show a sitemap

`GET /api/sitemaps/{id}`

`200` returns the sitemap, and an absent one `404`.

### Create a sitemap

`POST /api/sitemaps`

```json
{
  "name": "Main",
  "path": "main.xml",
  "kind": "Sitemap",
  "enabled": true,
  "containedSitemapIds": []
}
```

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | Yes | At most 128 characters, without control characters or the characters reserved in file names. |
| `path` | string | No | A relative path ending with `.xml`, validated like the admin editor. Blank derives it from the name. |
| `kind` | string | No | `Sitemap`, the default, or `SitemapIndex`. |
| `enabled` | boolean | No | Whether the public route answers. Default `true`. |
| `containedSitemapIds` | array of strings | No | For an index only: distinct, existing regular sitemaps. |

`201` returns the sitemap, with a `Location` header. An invalid definition returns a `400` validation problem keyed by property.

The identifier is generated by the server, and the path identifies the sitemap at creation: repeating the request with the same definition returns `200` with the stored sitemap, without writing anything, and a different definition under the same path returns `409`.

### Update a sitemap

`PUT /api/sitemaps/{id}`

Replaces the definition, with the body of creation, and keeps the sources. `kind` can't change. Omitted properties get their default, so an omitted `enabled` enables the sitemap. An absent sitemap returns `404`. An equivalent update doesn't write anything.

### Delete a sitemap

`DELETE /api/sitemaps/{id}`

Returns `204`, and `404` when the sitemap is absent. The indexes referring to it have their cache invalidated.

### Enable or disable a sitemap

`POST /api/sitemaps/{id}:enable` and `POST /api/sitemaps/{id}:disable`

Return `204`, also when the sitemap is already in that state, without writing anything. An absent sitemap returns `404`.

## Sitemap sources

### List source types

`GET /api/sitemap-source-types`

Returns the source types with a typed contract among the registered ones: `ContentTypesSitemapSource` and `CustomPathSitemapSource`, depending on the enabled features.

```json
["ContentTypesSitemapSource", "CustomPathSitemapSource"]
```

### Get a source schema

`GET /api/sitemap-source-types/{type}`

`200` returns the JSON Schema of the source's `configuration`, without the identifier and the update time, which belong to the server. An unknown type returns `404`.

### List sources

`GET /api/sitemaps/{id}/sources`

```json
[
  {
    "id": "8c1n4y7rt",
    "type": "CustomPathSitemapSource",
    "supported": true,
    "configuration": {
      "path": "contact",
      "changeFrequency": "Monthly",
      "priority": 5
    }
  }
]
```

A source of another type exposes its identity only, with `supported: false` and a null `configuration`. An absent sitemap returns `404`.

### Create a source

`POST /api/sitemaps/{id}/sources`

```json
{
  "type": "CustomPathSitemapSource",
  "configuration": {
    "path": "contact",
    "priority": 5,
    "changeFrequency": "Monthly"
  }
}
```

`configuration` must be complete, and unknown properties, `id` and `lastUpdate` are rejected. Priorities range from `0` to `10`, and change frequencies use their enum names. `ContentTypesSitemapSource` only accepts existing routable content types. Sources can only be added to a regular sitemap: update the `containedSitemapIds` of an index instead.

`200` returns the source. An invalid definition returns a `400` validation problem, and an absent sitemap `404`.

The identifier is generated by the server, so repeating a successful request creates another source. After an uncertain response, list the sources before retrying.

### Update a source

`PUT /api/sitemaps/{id}/sources/{sourceId}`

Replaces the complete configuration, with the body of creation. `type` can't change. An absent sitemap or source returns `404`. An identical configuration doesn't write anything. A change regenerates the sitemap's cache identifier.

### Delete a source

`DELETE /api/sitemaps/{id}/sources/{sourceId}`

Returns `204`. An absent sitemap or source returns `404`, and an index `400`.

## Errors

Failures use Problem Details, except invalid definitions, which use a validation problem keyed by property.
