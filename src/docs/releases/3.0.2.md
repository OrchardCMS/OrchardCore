## Orchard Core 3.0.2

**Release Date:** Not yet released

This is a bug fix and security release for Orchard Core 3.0. It contains fixes for several security issues, including tenant media isolation, path traversal in static file resolution, and missing authorization checks, as well as fixes for newly discovered bugs and updates to vulnerable packages.

As a patch release, it is compatible with v3.0.0 and v3.0.1 and can be used as a drop-in replacement. However, some of the security fixes tighten validation and authorization. Please review the upgrade notes below before upgrading.

## Upgrade Notes

### Media `AssetsPath` Must Be a Relative Tenant Subdirectory

The `OrchardCore_Media:AssetsPath` setting must now be a relative subdirectory of the tenant's data directory (`App_Data/Sites/{tenant}` by default). Absolute paths, drive prefixes (including drive-relative paths such as `C:Media`), `.` or `..` segments, empty segments, and segments ending in a dot or space are rejected, and Media options validation fails at startup.

To store tenant data on another volume, configure the host's application data location instead, for example, with the `ORCHARD_APP_DATA` environment variable. See [Media storage location](../reference/modules/Media/README.md#media-storage-location) for more details.

Similarly, the `TargetPath` (or `Path`) of files imported by the `media` recipe step must be a relative file path without traversal segments. Rooted paths and paths that contain `:` or `..` are rejected. See [Recipe media imports](../reference/modules/Media/README.md#recipe-media-imports).

On non-Windows systems, the file system store now compares its root path case-sensitively.

### GraphQL Named Queries Require Query Permissions

SQL, Lucene, and Elasticsearch queries exposed as GraphQL fields now enforce the same permissions as the queries API. In addition to the permissions required to use GraphQL, callers need one of the following permissions:

- `ExecuteApi_{QueryName}` (Execute Api - {QueryName}) for a specific query.
- `ExecuteApiAll` (Execute Api - All queries) for all queries.
- `ManageQueries`, which implies the two above.

If anonymous or limited-role GraphQL clients use named queries, grant the corresponding permissions to their roles, otherwise their requests will fail authorization.

These permissions are now also available from the new `OrchardCore.Queries.QueryPermissions` class in the `OrchardCore.Queries.Abstractions` package. The existing `OrchardCore.Queries.Permissions` members still exist and keep the same permission names.

### Elasticsearch Index Info and Query Admin Pages Require Permission

The Elasticsearch index info (`Admin/Elasticsearch/indexinfo/{id}`) and index query (`Admin/Elasticsearch/query/{indexName}`) admin pages now require the `ManageElasticIndexes` permission, which is implied by `ManageIndexes`.

### Application Static Files

Static files served under the application's own module path are now resolved through the web root file provider, which prevents path traversal outside of `wwwroot` and respects a custom `WebRootPath`. `ModuleEmbeddedStaticFileProvider` no longer serves the application's own files. This only affects code that instantiates it directly.

### Absolute URLs

`IUrlHelper.ToAbsoluteUrl()` now returns URLs that already start with `http://` or `https://` unchanged. This fixes SEO meta tags such as Open Graph and Twitter images when media is served from a CDN.

### Package Updates

Several dependencies were updated to address vulnerabilities, including `Microsoft.SourceLink.GitHub` (for [GHSA-23fw-v26w-5fgq](https://github.com/advisories/GHSA-23fw-v26w-5fgq) in the transitive `Microsoft.Build.Tasks.Git` package), `AngleSharp`, `Microsoft.IdentityModel.Protocols.OpenIdConnect`, and the `Microsoft.AspNetCore.*` and `Microsoft.Extensions.*` 10.0 packages. If your projects pin lower versions of these packages, update them to avoid NuGet package downgrade errors.

### `slugify` Liquid Filter

The `transliterate` argument of the `slugify` Liquid filter was removed before 3.0.0 and is ignored. The documentation has been updated accordingly. To transliterate text before creating a slug, use the [`transliterate`](../reference/modules/Liquid/README.md#transliterate) filter before `slugify`, for example, `{{ "Crème brûlée" | transliterate | slugify }}`.
